# measurements/ — hardware captures

Numbers measured on a physical robot, as opposed to taken from a datasheet. These are
**unreproducible**: each is a robot, a battery charge and an afternoon, and nothing here can
be regenerated by re-running code. That is why they live in one named place at the top of the
tree rather than under whichever tool happened to write them.

`bittle_io` writes here by default (`record.DEFAULT_ROOT`, resolved from the module file so it
does not depend on the working directory). Override with `--out`.

```bash
uv run --directory deploy python -m bittle_io --port $PORT --run-id my_session probe
uv run --directory deploy python -m bittle_io report measurements/my_session
```

## What is here

`reference/` is one complete session — probe, per-joint sweeps, step responses, latency and
command-rate traces. It is where the actuator constants in `sim/` come from, and it is what
a new capture should be compared against.

`before_flash/` and `after_flash/` are a matched pair across the firmware change that
introduced realtime mode, and only mean anything read together:

| | before_flash | after_flash |
|---|---|---|
| firmware | B10_260717 | B10_260820 |
| realtime mode | not supported | supported |
| gP stream | 249.2 Hz (always) | 5.0 Hz stock / 248.9 Hz realtime |
| command → motion | 54 ms | 54 ms |
| 50 Hz command rate | — | 50.0 Hz, 0/500 overruns |

They are deliberately NOT merged into `reference/`. Two sessions on two firmware builds in
one directory is the provenance error this file warns about below: `manifest.json` records
what a number is, not which robot-afternoon produced it.

## Read CAVEATS.md before consuming a number

Some recorded values are **invalid and are kept anyway**, because deleting a measurement
hides that it was attempted. `manifest.json` is a summary, not a verdict: it records fit
parameters without recording fit quality, so a failed fit and a good one look identical
there.

Two live examples, both documented in `reference/CAVEATS.md`:

- `manifest.json → step → tau_ms` reports the *slowest* tau across amplitudes regardless of
  R², which can select a fit worse than a constant. The usable row is in `step_summary.csv`.
- Every `step` and `sweep` number in `reference/` is an **aliasing artifact**. Both poll joint
  feedback at ~15 Hz, and with the firmware interpolation ramp removed the plant is too fast
  for that sampling rate.

Where a session has a `CAVEATS.md`, it is the authority for that session.

## Where these numbers end up

| measured quantity | lands in |
|---|---|
| actuator tau / slew, action + IMU latency, observation noise | `sim/mj_vec_env.py` |
| domain-randomisation ranges | `sim/config.py` |
| MJCF gains fitted to the step response | `model/bittle.xml` (`kv`, `armature`) |
| joint index / sign / offset | `deploy/joint_calibration.py` |
| the tau / slew a deployed policy observes with | inside each `deploy/policy/*.npz` |

Paths in code comments are written repo-root-relative — `measurements/reference` — because
these files are read from several working directories.
